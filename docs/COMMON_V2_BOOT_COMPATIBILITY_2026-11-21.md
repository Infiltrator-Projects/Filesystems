# Common V2 filesystem qualification

## Scope and evidence

This checkpoint covers all 23 independent repositories. The ABI authority is [Libraries at d23a526](https://github.com/Infiltrator-Projects/Libraries/blob/d23a52693fd3212368d327e1c1302e07ae9510ec/include/infiltratr/filesystem_module_v2.h). Each released AMD64 Debian asset was checked against its GitHub SHA-256 digest, extracted, and opened through `infiltrator_filesystem_api_v2` on an isolated test host. All 23 descriptors passed the header's `ifs_fs_api_v2_valid` check. All 23 candidate native installer source archives were extracted, rebuilt and exercised separately with their provider tests. The published package versions in the table are unchanged. The table records separate inspections of the actual exported symbols, the exact embedded ELF where present, and locally built providers.

**The rebuilt BOOT validator result is unavailable for every module.** The rebuilt v0.1.164 package has no `validate-module` executable. Its source at 47f65bb documents that it currently uses EFI filesystem drivers and lacks an authenticated Common V2 module loader. There are zero released modules with a verified kernel and initramfs read through that consumer. SWAP has no file namespace and its applicable consumer check is deliberate exclusion as a boot volume. [BOOT validation contract](https://github.com/Infiltrator-Projects/Boot/blob/47f65bb6528b62462c8d389d8b63a4fe8c8d9e18/docs/VALIDATION.md#common-v2-qualification-gap) · [Rebuilt BOOT release](https://github.com/Infiltrator-Projects/Boot/releases/tag/v0.1.164)

A **namespace** descriptor advertises probe, read-only mount/unmount, stat, directory enumeration and read. **Embedded** means the carrier contains a second ELF with a freestanding/firmware descriptor. **Direct** means the installed ELF itself declares those profiles. **FS** means it declares freestanding only alongside hosted. A right arrow shows a change from the published binary to the audited main source. Additional symbols get an explicit V1 flag when they export a retired filesystem entry point. Tests are the provider's normal source test suite or portable standalone checks. Action links identify the exact build revision. “Blocked” in the validator column records that the executable could not be invoked.

## Binary and media findings

Twenty of the 22 boot-volume formats currently provide hosted CORE file and directory operations, and 19 provide them in a firmware-profile ELF. APFS and ZFS still lack CORE namespace operations. NTFS currently depends on ntfs-3g for its hosted namespace. SWAP is separate.

The Debian packages for APFS, Btrfs, NTFS, SFS and SFS2 contain actual filesystem-specific kernel modules. Each of the five releases also advertises a standalone kernel module asset. APFS, NTFS and ZFS additionally export their format-specific V1 entry point. The remaining released ELF files did not export a V1 filesystem entry point. Across the candidate source trees the package checkers now require the exact installed filesystem module and manual.

Btrfs exercised both the hosted carrier and its extracted, byte-identical no-import ELF on an independent `mkfs.btrfs` image. Both returned the original Debian kernel and compressed initramfs byte-for-byte on 512-byte and 4096-byte hosts. Independent corruption of both metadata replicas and of file data returned a corruption error. An injected host read failure returned an I/O error. Complete image hashes matched before and after testing. The supported subset includes CRC32C, uncompressed file extents, and single-device SINGLE/DUP profiles. [Btrfs reader](https://github.com/Infiltrator-Projects/Filesystem-Btrfs/commit/4ec22441c06562b9ded17d3020cd27d67c3d0fdd)

OFS read the kernel and compressed initramfs from a disposable image produced by amitools on 512-byte and 4096-byte hosts. Changing another byte in the same OFS data block caused a one-byte read to fail its checksum. Both media hashes stayed unchanged. A separate test distinguishes a root-sector I/O error from a damaged root checksum. The standalone V2 defragmentation export remains present. [OFS reader and packaging](https://github.com/Infiltrator-Projects/Filesystem-OFS/commit/58e9e2e750e1f84591f025709338df5e3c29f099)

The native installer source archives exclude obsolete V1 SDK data and separate Linux, Windows and EFI driver trees. For all 23 formats the source archive was unpacked into its own directory and the included provider built and tested there. No new release was issued.

ZFS now checks the OpenZFS SHA-256 ECK of both vdev configuration and uberblocks at their native physical offsets. A real big-endian reference pool and a newly generated little-endian 4Kn OpenZFS pool were recognised on 512-byte and 4096-byte hosts. One bad redundant label was tolerated. Corrupting all label configurations, damaging the uberblock rings, or moving intact labels to the wrong physical location was rejected. Test images kept their original SHA-256. Files and directories are still unavailable through the ZFS provider. [ZFS probe and tests](https://github.com/Infiltrator-Projects/Filesystem-ZFS/commit/2c61ff07988e765712939eb2ebf79dc3fb3f7ec1)

The exFAT carrier’s embedded ELF was extracted and exercised through the public V2 API. Image checks cover a real exfatprogs volume, file and directory reads, and rejection of corrupted and checksum-valid malformed metadata. The provider and BOOT checks run independently. [exFAT package and test changes](https://github.com/Infiltrator-Projects/Filesystem-exFAT/commit/33ef7124f2d4449ac61a158a72c6f1063af57602)

XFS checks duplicate sector, inode and allocation-group geometry and the directory block-size limit. Valid xfsprogs images were exercised with three host sector sizes. Independently re-checksummed contradictory metadata, raw CRC damage and host I/O errors were distinguished. [XFS geometry and package tests](https://github.com/Infiltrator-Projects/Filesystem-XFS/commit/fa11e81f2bda48559b80b9f6aeb3f35de2d93d0e)

XFS now uses the same reader in hosted and firmware profiles. It enumerates real v4 and v5 directories and reads a kernel and initramfs byte-for-byte. A disposable Linux fixture guest independently created a sparse file whose mapping required a bmap tree. The module returned all expected bytes after clean unmount, refused a separate volume with a pending log and rejected a checksummed bmap block with a wrong owner. The data-device images were opened read-only for qualification and their hashes were verified. [XFS native namespace and firmware tests](https://github.com/Infiltrator-Projects/Filesystem-XFS/commit/05a9466b2e9cb56b6c562adb3b70ae701d2d5acf)

PFS3 reads a kernel and initramfs from a PFS volume independently formatted and populated by Hst Imager. The same media was exercised with 512-byte and 4096-byte host transfers via the hosted carrier and its extracted ELF. Both readers rejected a corrupted anode index. All image hashes matched. Mount lifetime testing also checks that a reentrant close returns busy while a read is active. [PFS3 code, media tests and release gate](https://github.com/Infiltrator-Projects/Filesystem-PFS3/commit/8efd596d4b500b02a4ae0a2f8d66a8fbbfd560f0)

A disposable OVMF trial started the rebuilt 0.1.164 EFI executable from the canonical BOOT path with the packaged PFS3 module staged and independently populated boot media attached. BOOT reached its menu. The test did not observe the kernel handoff or the initramfs marker. The run produced no positive BOOT result.

The APFS probe now accepts the ephemeral NX superblock on an independently formatted, `apfsck`-verified container. The hosted and import-free firmware builds share this probe. Both rejected Fletcher checksum damage and a checksum-valid superblock with an incorrect object storage class on 512-, 4096- and 8192-byte hosts. All image hashes were preserved. Only probe is advertised in firmware. [APFS shared probe and tests](https://github.com/Infiltrator-Projects/Filesystem-APFS/commit/1df09ab7a5b8243d8c8536bf27853843bba35823)
